“Linux 不是神”评论存档

Linux is free if your time is free。视频里说的大部分都是深度定制的自由带来的代价（换句话说，如果你不需要深度定制，就别用 linux 了）。

不如来看看 windows 是怎么处理视频中的问题的。

安装

大多数电脑都预装了 windows，大多数软件的收回首先支持 windows，得益于 windows 的市占率。

硬盘分区

一般都是电脑厂商分好的。普通用户接触不到。如果你自己安装 windows 也会有这个问题。

swap 文件

Windows 也有类似的东西就是分页文件，大致功能就是在内存不足的使用用部分硬盘来代替。但是大多数用户也接触不到。

包管理器和依赖。

大多数 windows 都喜欢把链接库和可执行文件打包在一起分发，自然就没有依赖问题（你可以找找你的 windows 里有几个 ffmpeg）。打个比方，假设你需要请工人来造船，但是工人显然不能空手造，需要一定的工具，并且不同的工人可能需要很多种不同的工具。但是这些工具有一个特点，就是只要工具种类相同，那么需要一份工具，所有人都能同时使用（我知道很别扭，但是请先接受这个设定）。

你有两个选择：可以让所有工人自备工具（这是 windows 选的）或者先问好工人需要哪些工具，你自己准备一份（linux 选择的）。

容易发现前者可能造成浪费（毕竟，相同种类的工具只需要一份），而后者需要你知道每个工人需要哪些工具（这就是包管理器的主要工作）。

驱动

Linux 从 init system 到 de 都提供了很多种选择，并且每个选择需要做的操作都是不一样的，让安装程序适配所有选择显然不现实（比如，假设你适配了当前所有的 de，这个时候有人重新写了一个新的 de，你可能又要去重新适配），因此直接让用户自己处理这部分操作。

Windows 只提供一种选择（gui 都写在内核里了），这样大多数驱动安装程序都可以自动处理。

cli 和 gui

cli 确实不适合直接给普通用户用。Windows 的大部分常用操作都有 gui。Linux 则没有，因为 cli 好写（划掉）并且服务器上没有桌面环境。

Unix 的哲学是 do one thing and do it well。Gui 并不是软件的必备组成部分。实际上很多软件也有 gui 包装。并且 cli 可以通过管道组合使用实现自动化。gui 则比较困难。

并且 ui 设计是一件十分困难的事情。许多 cli 可能有几十个选项，并且有些选项有子选项。为其中的所有接口都包装显然不现实（想要的功能被放在了一个 n 级菜单里显然不是理想情况），并且包装了也没那么好用，遇到专业词汇还是要查意思。

实际上如果你深入折腾过 windows 也难免接触这些（普通用户接触不到，而且根据我的经验 windows 有些部分的文档比较烂）。

linux 选择将所有的复杂性暴露给用户，而 windows 则选择包装成 gui 藏起来。

总而言之，请根据自己的需求选择系统，而不是人云亦云，盲目跟风。
